# План: починить упавший Docker build

## Что произошло

Run #667 упал на шаге `Build image locally` за 30 секунд. Упал внутри `RUN npm run build` в Dockerfile (строка 19), то есть сборка даже не дошла до SSG-этапа.

## Причина

В прошлом ответе я создал `.dockerignore` со списком, который включал `.env` и `.env.*`. Это **исключило файл `.env` из Docker build context**.

Проверки:
- `.env` физически есть в репозитории и НЕ находится в `.gitignore` — значит он коммитится и попадает на GitHub Actions runner после `actions/checkout`.
- В `.env` лежат `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`, `VAPID_*` — все нужны для сборки.
- Memory `mem://infrastructure/ssg-env-parsing-logic` явно фиксирует: «Environment variables в .env парсятся вручную в `vite-plugin-ssg.ts`».
- На сервере (скрин 1) сборка прошла за 236s и выдала «SSG pages: 1289» — значит на сервере `.env` присутствует. На CI его «съел» `.dockerignore` → build упал.

На локальной сборке (скрин 1) `.dockerignore` ещё не существовал в момент клонирования / билда (это раньше моего изменения), поэтому там всё ОК.

## Действие (одно изменение)

Переписать `.dockerignore`, убрав `.env`, `.env.*` и `*.md`. Финальное содержимое:

```
node_modules
.git
.gitignore
*.log
.lovable
dist
.github
README.md
```

Что убрано и почему:
- `.env`, `.env.*` — **критично нужны** для сборки (Supabase ключи, VAPID).
- `*.md` — оставлять опасно (если позже подключат markdown-контент блога — снова сломает). Оставляю только `README.md` точечно.

Что оставлено:
- `node_modules`, `dist` — основной выигрыш по размеру контекста (≈150MB).
- `.git`, `.github`, `.lovable`, `*.log`, `.gitignore` — мусор для билда.

## Что НЕ трогаем

- `Dockerfile` — без изменений.
- `.github/workflows/docker-build.yml` — без изменений (двойную сборку и `concurrency` оставляем как есть, это отдельная задача).
- Никакие исходники, edge-функции, конфиги — не трогаем.

## Ожидаемый эффект

- Следующий push → workflow видит `.env` в контексте → `npm run build` отрабатывает SSG → smoke-check проходит → push в Docker Hub.
- Размер контекста остаётся ~5MB вместо 162MB (исключения `node_modules` + `dist` + `.git` дают почти всю экономию).

## Про двойную сборку (не делаем сейчас)

Анализ пользователя про `load: true` + `push: true` = двойная сборка — верный, но **не относится к падению**. Это оптимизация на потом, отдельным изменением, после того как основная сборка снова стабильно зелёная. Не смешиваю в один фикс — урок прошлой недели.
