## Цель
Сделать пагинацию блога на мобильном идентичной скриншоту/UX‑ожиданию: компактная подгрузка по 10 шт, авто‑загрузка при скролле к низу списка и аккуратная fallback‑кнопка во всю ширину на мобильном. Только фронтенд `src/pages/Blog.tsx`.

## Текущее состояние
- `visibleCount` стартует с **30** — на мобильном это слишком тяжёлый первый рендер (30 карточек × ~140px ≈ 4200px скролла).
- Шаг догрузки **+30**.
- Кнопка «Показать ещё» — `variant="outline" size="lg"`, инлайн по центру, без full‑width на мобильном.
- Авто‑догрузки по скроллу нет.

## Что меняем
1. **Начальный лимит**: `useState(10)` (вместо 30). Десктоп тоже получит 10 — это нормально, т.к. сразу подгрузится дальше при скролле.
2. **Шаг догрузки**: +10 (вместо +30) — соответствует мобильному ритму.
3. **Сброс при смене категории/сортировки**: оставляем сброс на 10 (`setVisibleCount(10)` в обработчике клика категории; добавить тот же сброс в `useEffect` на смену `sortBy`).
4. **Авто‑догрузка**: добавить `IntersectionObserver` на sentinel `<div ref={sentinelRef} />` сразу под списком. При пересечении viewport (rootMargin `300px 0px`) — `setVisibleCount(c => c + 10)`. Срабатывает только если `visibleCount < filteredPosts.length`. Чистим observer в cleanup.
5. **Кнопка «Показать ещё»** как fallback (для пользователей с включённым reduced‑motion / без JS observer):
   - `w-full md:w-auto`
   - `variant="secondary"` (вместо `outline`) — лучше читается на тёмном фоне
   - размер `default` на мобильном, `lg` на десктопе
   - надпись прежняя: `Показать ещё ({remaining} осталось)`.
6. **SSR‑guard**: `IntersectionObserver` запускать только в `useEffect` (он сам по себе клиентский, но дополнительно проверим `typeof IntersectionObserver !== 'undefined'`).

## Ожидаемый результат
На мобильном изначально видно ~10 карточек, при скролле к низу плавно подгружается ещё по 10. Кнопка «Показать ещё» видна как fallback, занимает всю ширину контейнера и выглядит цельно с тёмной темой.
